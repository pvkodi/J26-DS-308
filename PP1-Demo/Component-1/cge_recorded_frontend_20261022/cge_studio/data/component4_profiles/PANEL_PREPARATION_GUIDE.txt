COMPONENT 4 RISK PROFILES — PRESENTATION AND QUESTION GUIDE
Study completed21 October2026

1. THE ONE-MINUTE EXPLANATION

We built separate empirical behaviour profiles for Qwen2.5-7B-Instruct and
Granite-3.3-2B-Instruct. A profile describes how a model's obligation failure rate
changes under specified conversation conditions. We varied context length,
instruction placement,previous exchanges,active obligation count,and request
detail. We generated real answers and checked four explicit rules using code.
We also ran scripted multi-turn conversations with genuinely generated histories.
The profiles are a separate Component4 handoff. They do not replace or modify
the existing predictor calibration profiles. We trained no new model in this run.

Think of testing vehicles on specified roads. The reference road measures each
vehicle's starting performance. The change on a difficult road measures its
sensitivity. A vehicle can have poor starting performance but a small sensitivity
increase. Neither number alone completely describes the vehicle.

2. WHAT WAS COLLECTED

Two pinned open-weight models were run on a Kaggle Tesla T4 using NF4 weight
quantization with FP16 computation. Temperature0.7,top_p0.9,max768 output tokens.
The same generation protocol was used for both models. Repo revisions,versions,
seeds,timestamps and hashes are retained. A seed helps reproducibility but does
not guarantee identical output on all hardware/software combinations.

Controlled study:
2 models x4 scenario families x12 conditions x3 sampling repeats =288 answers.
Each repeat uses the same prepared input for that condition with a recorded seed.
The four task families are support handover,project planning,incident triage,
and event coordination. They use authored fictional facts and related handover
tasks. They are not a representative sample of every possible conversation.

Self-generated multi-turn check:
2 models x2 additional families x2 paths x12 answer turns =96 answers.
The extra families are equipment rotation and oral archive scheduling.
There are8 conversations in total,4 per model. User requests remain scripted.
Natural means model-generated preceding assistant answers,not a human field study.

Total384 generated answers. Each is checked against4 focal obligations,which
gives1536 focal observations. Extra competing rules bring all recorded checks to
1920. Four labels on one answer are correlated,not four independent conversations.
One Granite controlled answer reached the output cap.383 completed answers and
1532 focal checks are valid for primary completed-answer analysis.

3. THE FOUR FOCAL OBLIGATIONS

A. Below120 words. Exactly120 fails. Words are ASCII letters/digits,with an
optional internal apostrophe,as defined by the collector's regular expression.
B. End with the scenario's exact ending phrase. Case and punctuation matter.
Extra text or quotation marks after the phrase fail. Surrounding outer whitespace
is ignored by text.strip() before checking the ending.
C. Do not use the ASCII comma character ','. This checker is not a test of all
Unicode punctuation that resembles a comma.
D. Include the whole word provisional,ignoring case. Provisional passes;
provisionally does not satisfy this whole-word requirement.

The8-rule conditions add:never use guarantee;exactly3 hyphen bullet lines;
clarify exactly twice;at least2 different lowercase square-bracket placeholders.
All8 are compatible. A short constructive example passes them simultaneously.

Only the same4 focal rules enter primary comparisons. Otherwise adding difficult
rules would change the scoring denominator and contaminate the comparison.
Additional rules are retained in all_rule_checks.csv and original records.

4. CONTROLLED HISTORIES VERSUS SELF-GENERATED HISTORIES

In the controlled study,we authored previous user/assistant exchanges. Every
assistant example satisfies all8 rule formats. This holds even in4-rule inputs,
so the supplied history can be shared across obligation-load comparisons.
The target next answer is then generated by the actual model.

This asks:given an entirely compliant supplied history,how often does the next
answer violate a focal requirement under this condition?

It does not mean the model naturally produced every earlier compliant answer.
The common history can teach or prime an output style through examples.

In the self-generated check,the first model answer becomes part of the next
input,and this continues for12 answers. Failures,initial violations,recoveries
and repeated violations can occur. User messages and background additions are
still scripted. Different models and paths develop different histories.

Do not describe all384 answers as384 independent natural conversations.

5. THE BASELINE AND12 CONDITIONS

Reference:approximately2048 native prompt tokens,12 prior exchanges,4 rules,
the rule block early in SYSTEM,and a concise current request.

The12 conditions are:

3 long context:8192 tokens
4 rule block in the middle of SYSTEM
5 rule block late in SYSTEM
6 only4 previous exchanges
7 twenty previous exchanges

9 detailed current request
10 long context plus8 rules
11 long context plus late system block
12 long context plus detailed request

A prior exchange means one user message plus one assistant answer. Twelve prior
exchanges means the next target answer is answer13. A token is a model processing
unit,not a word. Prompt size includes system instructions,history,current user
message and native chat-template markers. It excludes the answer to be generated.

Neutral complete background records bring each input near the native token
target. Material is adjusted when turn count,rule count or request length changes,
so those comparisons remain at approximately the same total context size.
The last4 supplied exchanges match for the4/12/20-turn controlled comparisons.
No instructions or history are silently truncated. Exact native counts are saved.

Padding quantities differ slightly between model tokenizers. Case facts,rules
and the ordered neutral material match;the complete input bytes are not identical.
Moving instructions stays in SYSTEM and preserves priority. Late SYSTEM position
does not mean the end of the entire chat:conversation history still follows it.

Each model has its own reference failure rate. Qwen is also the named reference
model for comparing sensitivity changes. Twenty models are unnecessary for these
comparisons. Twenty or more would be relevant to population rankings/percentiles,
which this study does not claim.

6. HOW A PROFILE SCORE IS CALCULATED

Step1:for each valid answer,label each focal rule pass0/fail1.
Step2:average its4 labels. An answer failing1 of4 has a focal failure value0.25.
Step3:match reference and changed answers by family and repeat.
Step4:subtract reference value from changed value for each pair.
Step5:average repeats within each family,then give each of4 families equal weight.

Signed sensitivity = changed-condition failure rate minus reference failure rate.
0.20 means20 percentage points more failures under that comparison.
It is not20% absolute failure probability and is not a score normalized across
all models. It is not a learned feature-importance weight.

Harmful sensitivity = max(0,signed sensitivity). If performance improves,the
signed result is negative and the harmful-only result is0. Keep both fields.
Zero does not mean the model never fails or that the factor cannot matter.

Actual simple calculation for Qwen detailed requests:
Reference:6 failed checks among48 focal checks =12.5%.
Detailed:25 failed checks among48 focal checks =52.08%.
Difference:52.08%-12.5%=39.58 percentage points;score0.3958.
These48 checks come from12 answers,not48 independent model generations.

Granite detailed requests:14/48 reference versus38/48 detailed,an increase of
50 percentage points. Again,the answer-level failures may overlap across rules.

The capped Granite long-context answer and its paired reference are excluded
from that contrast. One family has2 valid repeats rather than3. Families still
receive equal weight. This explains the context row's different matched reference
rate28.125%,versus29.167% in fully observed reference comparisons. It is not an
arbitrary baseline change. Cross-model comparisons use the common valid pairs
for BOTH models,so use the dedicated comparison JSON rather than subtracting
separately averaged profile summaries.

Detailed requests are the clearest common source of deterioration in these data.
Granite shows a substantial controlled context increase. Qwen's context estimate

More rules do not necessarily hurt in this experiment. Added bullet/frequency/
placeholder rules shape the output,and short structured answers can satisfy
other requirements more easily. This identifies adding THESE rules,not a pure
universal effect of rule count. More compliant examples may also reinforce an
output pattern in the longer supplied histories. That is a plausible explanation,
not a discovered internal mechanism.

Low context sensitivity at a concise reference request does not mean Qwen is
safe in long detailed conversations. Its long-plus-detailed condition has62.5%

10. UNCERTAINTY AND THE CAPPED ANSWER

Most controlled cells have12 answers:4 families x3 repeats. One has11 valid
completed answers. Seed repeats are related observations. The four labels on
an answer also share the same generation.

Exploratory bounds resample the4 family-level effects with replacement and take
percentiles of the resulting mean effects. The runner exports300 bootstrap draws.
With only4 families,do not claim precise statistical certainty. Intervals crossing
0 leave the direction unclear. Null intervals can mean insufficient observed
variation;they are not proof of perfect certainty. No multiple-comparison claim
of statistically significant universal effects is made.

Qwen context interval is approximately-8.3 to+16.7 percentage points.
Granite context interval is approximately+13.5 to+29.2 points.
The matched Granite-minus-Qwen context difference is18.75 points,with an interval
touching0. Report an observed difference rather than a universal significant ranking.

One Granite long-context answer hit768 output tokens and contained546 counted
words with repetitive text. It is an operational failure,not a clean pass. The
frozen protocol excludes capped answers from primary completed-answer estimates;
raw prefix checks remain in the dataset. Do not silently relabel or delete it.
Treating its unknown overall outcome conservatively at either extreme gives a
Granite context increase between14.6 and22.9 points. The positive pattern survives
this bound,but more data are still needed for a precise estimate.

11. TECHNICAL TERMS IN PLAIN LANGUAGE

Black-box-style evaluation:inspect inputs and outputs without using gradients,
attention maps or internal activations to explain failure. We have local model
weights for execution but do not use mechanistic information in these profiles.
NF4:compress model weight storage to roughly4 bits in an inference format.
Computation usesFP16;this does not mean every operation is4-bit arithmetic.
Temperature0.7 and top_p0.9:settings controlling which plausible next tokens can
be sampled. Repeated seeds measure some output variability.
768-token budget:maximum generated output length. Tokens are not words.
Quantization/model revision:part of the evaluated configuration. Do not assume
the same profile applies to full precision,a different quantization or a new model.
Wall time:runner time including loading/reporting,about96.5 minutes. Kaggle may
also bill setup,idle time and allocated accelerators;its displayed quota is separate.

downstream decision based on a score will improve. That needs its own evaluation.

13. QUESTIONS THE PANEL MAY ASK

Q:Did you train or fine-tune these models?
A:No. We measured fixed model behaviour and aggregated deterministic rule failures.

Q:Is this the same thing as the risk predictor?
A:No. This profile is an empirical model behaviour summary for Component4. The
existing predictor estimates pre-answer risk and has separate calibration artifacts.

Q:What is your profile's prediction accuracy?
A:This run does not train a classifier or make scored per-answer predictions.
Classifier accuracy is not its evaluation measure. We report rates,paired changes,
coverage,uncertainty and a separate self-generated conversation check.

Q:Are the answers hardcoded?
A:The experimental prompts and controlled histories are authored. All384 target
answers are actual model generations. Raw texts,configuration,seeds and commitment
records are included. The selected Excel examples are not the whole evaluation.

Q:How were failures labelled? Did Qwen judge itself?
A:Code checked the four precise obligations. No LLM judge or extractor was used
to decide these primary labels. Broader semantic detector evaluation is separate.

Q:Why only two models? Why use different sizes?
A:This is a bounded two-model pilot. It supports within-model and paired relative
comparisons. It cannot isolate size from architecture or rank a model population.

Q:Why no20-model baseline?
A:Each model supplies its own reference condition. Qwen is an additional named
comparison. A population-normalized ranking would require a larger reference set.

Q:Why are added obligations associated with fewer failures?
A:These additions change answer structure. Also,the common prior history already
demonstrates that structure. No universal overload conclusion follows.

Q:Does a0 sensitivity score mean safe?
A:No. It can mean no measured deterioration or an improvement under one comparison.
Baseline failure can still be high. Inspect signed effect,raw rates and uncertainty.

Q:Did you prove long context causes failures independently?
A:No. We used controlled operational changes. Context expansion also changes
background quantity and instruction distance. Position is tested at fixed length,
but the study does not establish a perfectly isolated causal mechanism.

Q:Did you test every combination?
A:No. There are12 frozen conditions with three selected joint conditions. It is
not a complete factorial study and cannot describe every interaction.

Q:What exactly counts as generalization here?
A:Additional scenario families and self-generated histories were inspected. Results
are mixed. This is limited transfer evidence,not proof of general performance.

Q:Can this profile be applied to the live model in the frontend?
A:The live model is Qwen3-4B,which differs from the measured Qwen2.5-7B. It needs
its own profile. A shared brand/family name does not make these scores valid for it.

Q:Can this dataset later train a predictor?
A:It can contribute scoped data,but it is small and structured. Split by whole
scenario/history groups,keep all labels from one answer together,and never use
current-answer text,word count,finish reason or its checker label as pre-answer
features. New held-out tests and calibration would still be necessary.

Q:How do you know the records are consistent?
A:The audit recomputed hashes,checker outcomes,prepared inputs,history chains,
commitment timing and profile estimates. Hashes show internal consistency,not
independent third-party proof of where a generation happened.

Q:What did you learn about the models internally?
A:No internal mechanism is identified. These are behavioural findings. Mechanistic
discovery research would require separate evidence from internals/interventions.

Q:What are the next improvements?
A:More independent scenario families,more repeats,different obligation sets,
counterbalanced formatting loads,additional models/configurations,and more
self-generated conversations. Freeze evaluation before further outcome-driven tuning.

15. CLAIM TO USE AND CLAIMS TO AVOID

Use:We produced preliminary model-specific profiles of exact-obligation failure
under controlled conversation conditions,with separate multi-turn checks and
auditable records. Detailed requests worsen average compliance in this study;
Granite shows greater observed controlled context deterioration.

Avoid:We trained a universal profiler;we achieved92% profile accuracy;every long
conversation increases risk;8 rules are always safer;0 means no risk;the scores
are independent causal weights;all384 answers are independent human conversations;
these profiles apply to any Qwen model;the profile is already integrated into
Component4 or into the predictor. None of those claims is established here.
